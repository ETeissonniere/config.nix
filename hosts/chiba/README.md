# Chiba

Chiba is a small network auxiliary host. It runs CoreDNS, Tailscale, Pocket ID, and a shared reverse proxy in separate containers.

It uses a static IP (handy for DNS) unlike our other hosts. Additionally, it runs on a relatively RAM limited
Raspberry Pi 5 (2Gb RAM only). As a result, we had to tune our configuration to keep usage low.

Following our `straylight` config, every service like CoreDNS or Tailscale are running within their own containers
with limited persistence. Additionally, this host does follow our immutable configuration, with a `tmpfs` for the
root partition, which has the nice benefit of helping preserve the SD Card.

## Pocket ID

Pocket ID is served at `https://id.teiss.org` by Caddy in the reverse-proxy container on chiba. NixOS ACME obtains and renews
its certificate through Cloudflare DNS validation, using public DNS to avoid the local `teiss.org` zone.
Before deployment, place the raw Cloudflare API token (not an environment assignment) in
`/persist/reverse-proxy/var/lib/acme-secrets/cloudflare-token` on chiba, owned by root with mode `0600`
and its parent directory mode `0700`. The token needs DNS edit and zone read access for `teiss.org`.
No inbound Internet port forwarding is needed; clients must resolve `id.teiss.org` through CoreDNS
and reach chiba over the LAN or Tailscale subnet route.

Nix manages the service and application settings, including the B&E Auth display name.
Users, groups, OIDC clients, and access rules are managed in the web UI and stored in the
persistent database; rebuilds do not overwrite them. Client secrets are generated by Pocket ID.
Back up `/persist/pocket-id`, including the database and encryption key, together.

On a fresh installation, create the first administrator at `https://id.teiss.org/setup`.
Manage additional accounts through the admin UI; public signup is disabled.
